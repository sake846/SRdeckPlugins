# STD-T98 公開仕様調査

調査日: 2026-08-31。対象: 1.1版を基にしたSRdeckの4FSK／PSK受信実装。

**現行2.0版の英語全文を入手できた。ただし、最新版でも第1編のPSK音声CODECとTCH組立は未規定であり、版を更新するだけではPSK音声を実装できない。**
4FSKの訂正内容と検証用資料は確認できた。今回、受信処理やCODECは変更していない。

## 対象機種の確定に伴う追記

追記日: 2026-09-01。

ユーザーから対象が **DJ-DPS72Wなどのライセンスフリー無線用トランシーバー** と指定された。
DJ-DPS72Wの簡易無線通信は **4FSK＋AMBE+2** と確認できたため、この機種の通常音声受信にPSK音声の追加は必要ない。
先の「PSK音声仕様が未規定」という調査結果は、この対象機種の受信を妨げる条件ではない。

| メーカー資料で確認した項目 | 本プラグインの扱い |
| --- | --- |
| 351 MHz帯、4値FSK、地上82ch送受信＋上空15ch受信 | 既存4FSKモードで対象周波数へ選局 |
| AMBE+2、同方式の3R/3T登録局と音声互換 | AMBEドングルで音声復号する。機種からCODECを抽出する必要はない |
| 登録局共通の標準秘話と、アルインコ独自の強化秘話 | 標準秘話は現在鍵、プリセット、全32767コードの順に通常音声から探索し、解除後の音声をドングルで復号する。強化秘話は未対応 |
| Air-InCom.Liteによるスマートフォン経由の通信 | 携帯網・Bluetoothの通信は対象外。簡易無線へ中継された351 MHz側は対象 |

参照: [DJ-DPS72W公式製品仕様](https://alinco-denshi.com/item/dj-dps72w/)、
[公式簡易取扱説明書1ページ](https://alinco-denshi.com/wp/wp-content/uploads/2025/01/djdps72w_doukon.pdf#page=1)。
ここでの対応判断は、公開仕様と現実装を照合した結果であり、DJ-DPS72W実機での検証結果ではない。
強化秘話や製造者独自メッセージを含む全機能への対応は主張しない。

次の検証対象は、DJ-DPS72Wの**簡易無線・通常音声・秘話なし**の複素IQとなる。
PSKの対象機種探しよりも、既存4FSK受信部の実機確認を優先する。
チャネルから周波数への換算と初期設定はREADMEの「対象機種 DJ-DPS72W」に記載した。

## 不足情報はどこまで埋まったか

以下のPDFページは表紙を1ページ目とする。括弧内は規格に印刷されたページ番号。

| 項目 | 2.0-E5で確認できたこと | 判断 |
| --- | --- | --- |
| PSK音声CODEC | 第1編第5章、PDF 65（1-59）でもアルゴリズム・音声相互接続性は未規定 | 未解決。AMBE+2やM-CELPと断定できない |
| PSKのTCH | 第1編4.1.8.2、PDF 53–54（1-47–48）でも音声／非音声の信号分解組立は未規定 | TCH内部の音声区切り・FEC・インターリーブは別資料が必要 |
| PSKの制御CRC | 第1編図4-6、PDF 52（1-46）を画像でも確認。回路と多項式はあるが、初期値・CRC読出順の明記は確認できない | 現実装の初期値0・S5先頭・最終反転なしは引き続き実機検証が必要 |
| PSKのスクランブル | 第1編4.1.10、PDF 56–58（1-50–52）のPN9と未定義6ビットを含む範囲を確認 | 現実装のTCH抽出・PN9消費位置と整合 |
| 4FSKの音声・秘話 | 第3編4.1.11、PDF 219–220（3-63–64）と第5章、PDF 229（3-73）で処理順を確認 | 下記の現実装と整合 |

参照: [2.0-E5本文](https://www.arib.or.jp/english/html/overview/doc/5-STD-T98v2_0-E5.pdf)。

4FSKの旧1.1版には「音声符号化前の49ビット」という紛らわしい表現があった。
現行版では、秘話を適用する対象が**誤り訂正前の49ビット情報**であることを確認できる。
受信側の既存処理は `72 bit → FEC復号 → 49 bit → 既知鍵で秘話解除 → 音声合成` で、この順序に合っている。
混在フレームでも音声スロットの時間位置に対応する秘話系列を使う処理を維持する。
AMBE+2は第3編の推奨方式であり、この規定を第1編のPSKへ流用する根拠にはならない。

## 公開資料による追加照合

### 規格の既存試験ベクトル

2.0-E5第3編7.5.2の送信ビット列を抽出し、既存テストのフレーム全体と比較した。

| 既存フィクスチャ | 2.0-E5の掲載PDFページ | 結果 |
| --- | --- | --- |
| `T98Tone` | 235 | 全384ビット一致 |
| `T98Silence` | 236 | 全384ビット一致 |
| `T98Private` | 238 | 全384ビット一致 |
| `T98Burst` | 235、236 | 同期語以降の全384ビット一致。先行プリアンブルは比較対象外 |

比較スクリプト: `temp/arib-t98/research/public/verify_public_vectors.py`。
結果: 同ディレクトリの `public-vector-comparison.json`。
既存のARIB STD-T98テストもRelease出力で再実行し、**14件すべて成功**した。
結果: `SRdeck.Tests/TestResults/arib-t98-public-research.trx`。
これは仕様例・合成信号での確認であり、実際の会話音声や中継機との相互接続試験ではない。

### Anritsuの独立した制御チャネル例

[Anritsu「デジタル簡易無線設備の送受信特性評価方法（4値FSK方式）」](https://dl.cdn-anritsu.com/ja-jp/test-measurement/files/Product-Introductions/Product-Introduction/ms2830a-jl23502.pdf)
の53–54ページには、通常音声・UC=1・製造者番号0に対して、RICH=`D5F7`、SACCH=`CE851464BC89407`という例がある。
既存の通常音声ベクトルからホワイトニングを解除すると、両方とも一致した。
この資料の例はホワイトニング前であり、無加工で受信器へ渡せる送信フレームではない。
同資料50ページにも、波形生成ソフト自身ではチャネル符号化等を行わない旨が記載されている。

これは4FSKの制御符号化を検証する資料として利用できる。PSKのCRCや音声形式の証拠には使えない。

### 公開CODEC実装・解説

- [mbelib-neo](https://github.com/arancormonk/mbelib-neo): AMBEの誤り訂正・パラメータ処理の参考実装。採用コミット・利用条件は既存の第三者ライセンス文書に記録済み。
- [pyambelib](https://github.com/tallcat4/pyambelib): 同じmbelib-neoのPythonラッパー。72ビットのAMBE FEC復号と49ビット音声パラメータの扱いを公開している。作者はSTD-T98への適用を未試験と明記しているため、PSK互換の根拠にはしない。
- [著者公開ページ「デジタル簡易無線の受信と解析 STD-T98編」](https://www.magistol.com/book/t98/): 公開目次・正誤表を確認。対象は4FSKとAMBEであり、PSKの不足仕様は補えない。有料の書籍本文・購入者専用資料は取得していない。

調査した公開一次資料では、**STD-T98第1編の特定機種についてCODEC・FEC・TCH配置を一式確認できる資料、または検証済みのPSK音声実装は見つからなかった**。
検索結果に出る他規格のAMBE実装や掲示板上の推測だけでTCHの解釈を決めない。

## 増波・中継と現実装

増波後は登録局が地上82チャネル＋上空15チャネル、400 MHz帯免許局が75チャネル＋中継用10対となる。
参照: [アイコムの増波説明](https://www.icom.co.jp/business/icom-journal/digital-radio/)。
割当の具体値は2.0-E5第3編3.6、PDF 177–183で確認できる。
150 MHz帯も含め、チャネル番号と周波数を単一の連続式だけで対応付けないこと。

現プラグインは周波数を直接入力できるため、新周波数を一律に拒否する実装ではない。
調査時点ではチャネル一覧・中継上下周波数の選択UIは未実装だった。
2026-09-01のUI変更で、登録局CH01～82とS01～15の選択・CH表示を追加した。
続く追加依頼で免許局UHFの75ch、VHFの28ch、中継D1～D10の上り/下り選択を実装した。
表3-4のVHF CH20～28はF1Eを含まないため、UIではデータ用と明示する。
中継を含む実機の受信確認は引き続き未実施である。
公開されている中継機の実例として [IC-RP6300CR](https://www.icom.co.jp/lineup/products/IC-RP6300CR/) を確認したが、製品説明は無線フレームの完全な仕様ではない。

**中継対応を理由にRICHのD=1を有効化してはいけない。**
2.0-E5第3編表4-7、PDF 198（3-42）でもD=1は予約値のまま。
中継経由の詳細動作は、対象機の資料・検証信号で確かめる必要がある。
今回の照合だけでプラグイン全体を「STD-T98 2.0完全対応」とは扱わない。

## T98の現行受信範囲

これは4FSK方式であるDJ-DPS72Wの通常音声受信には影響しない。
未確認の形式をAMBE+2へ投入する変更は行わない。
2026-09-21の要件変更で、無音・試験音を既知平文とする候補推定と自動適用は削除した。
2026-09-22に標準PN15秘話コードのプリセットを5件追加した。現在鍵を最初に試し、次に登録済みプリセットを比較し、
確定できなければ全32767コードをバックグラウンドで比較する。発見したコードは現在鍵へ自動設定・保存する。
自動探索の進行状況は「受信」タブに表示する。手動解析の処理は残しているが、現行UIには操作項目を設けていない。
実機IQ取得用に、選局済み48 kHz IQの直前20秒をWAV・JSON・周波数.gainへ保存する機能も追加した。
条件・操作・検証の詳細は[READMEの標準秘話の設定](README.ja.md#標準秘話の設定)を参照。
