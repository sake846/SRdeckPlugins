# ARIB STD-T98 4FSK / π/4 QPSK 受信プラグイン

ユーザー提供の **ARIB STD-T98 1.1版・第3編（4FSK）と第1編（π/4シフトQPSK）** に基づく、
SRdeck用の受信プラグインです。送信機能はありません。

2026-08-31に、無料公開の英語版 **STD-T98 2.0-E5** を追加調査しました。
最新版でもPSKの音声CODEC・TCH組立は未規定です。4FSKの既存試験フレーム4種は最新版と全ビット一致し、
秘話とFECの処理順も現実装と整合しています。最新版の全機能への対応を示すものではありません。
出典・改定内容・未解決事項は [公開仕様調査](PUBLIC-SPEC-RESEARCH.ja.md) を参照してください。

**4FSKのAMBE+2音声を聞くには、ThumbDV / DVstick 30などのAMBEドングルを接続し、COMポートを設定してください。
ドングルが利用できない場合は受信状態の表示のみです。PSKは復調・制御情報・TCH抽出までで、音声は未対応です。**
第1編4.1.8.2および第5章は、音声CODEC、TCHの音声ビット配置、音声の相互接続性を規定していません。
PSKの256 bit TCHを4FSKのAMBE+2へ渡すことはしません。
PSK音声の追加には、対象機種のCODEC・FEC・ビット配置の仕様と検証用IQが必要です。

## 対象機種 DJ-DPS72W

ユーザー指定のDJ-DPS72Wは **351 MHz帯・4FSK・AMBE+2** のデジタル簡易無線登録局です。
本プラグインでは**「詳細設定」タブの変調方式を4FSK**にします（初期値）。PSK音声の未対応とは関係なく、既存の4FSK音声処理が対象です。
根拠: [メーカー仕様](https://alinco-denshi.com/item/dj-dps72w/)、[簡易取扱説明書1ページ](https://alinco-denshi.com/wp/wp-content/uploads/2025/01/djdps72w_doukon.pdf#page=1)。

初回の実機確認では、無線機を簡易無線の通常通話・秘話なしに設定し、プラグインは同じCH番号、
UC=0（全UC）、秘話鍵=0、音声出力ONにします。AMBEドングルのCOMポートも指定してください。
UC=0の全UC扱いは本プラグインの設定です。
CH・UC・秘話鍵などの設定は、入力欄からフォーカスが外れると自動で適用・保存されます。

地上チャネルの周波数は、CH1～70が `351200000 + (CH - 1) × 6250` Hz、
CH71～82が `351031250 + (CH - 71) × 6250` Hzです。
例えばCH1は351.200000 MHz、CH15は351.287500 MHz、CH71は351.031250 MHz、CH82は351.100000 MHz。
**CH71で低い周波数へ戻るため、82チャネル全体を連続した周波数として計算しないでください。**
根拠: [STD-T98 2.0-E5 第3編・表3-6](https://www.arib.or.jp/english/html/overview/doc/5-STD-T98v2_0-E5.pdf#page=181)。

標準秘話は現在鍵、最大5件のプリセット、全32767コードの順に通常音声から自動探索します。
把握している秘話コードがある場合は、「受信設定」の現在鍵に指定してください。
アルインコ独自の**強化秘話は未対応**です。
Air-InCom.Liteのスマートフォン経由の通信も対象外です。簡易無線へ中継された場合は、その351 MHz側の信号が対象になります。
DJ-DPS72W実機のIQ・会話音声ではまだ検証していないため、機種固有機能を含めた動作保証はありません。
特定小電力・市民ラジオ等も含む「ライセンスフリー無線」全般への対応を意味するものではありません。

## 使い方

1. リポジトリのルートで `dotnet build SRdeck/SRdeck.csproj -c Release` を実行します。
2. `SRdeck/bin/Release/net10.0-windows/win-x64/SRdeck.exe` を起動し、
   プラグインから **デジタル簡易無線（STD-T98）** を有効にします。
   AMBEドングルをUSB接続し、WindowsのデバイスマネージャーでCOM番号を確認します。
   「受信設定」タブの「AMBE接続先」に `COM6` のように入力し、通信速度は通常460800 baudにします。
   詳しい設定と接続確認は下記の「ThumbDV / DVstick 30 を使う」を参照してください。
3. 画面上部の**種別**から登録局・免許局UHF/VHF・中継上り/下りを選び、**CH**を選択します。CH前後ボタンは押すと選局し、他の設定は入力欄からフォーカスが外れると適用・保存されます。
   CH−／＋は選択中の種別内で移動します。「呼出15」は登録局のみ有効です。
   登録局の地上CH01～82と上空用S01～15、免許局UHFの75ch、VHFの28ch、中継D1～D10の上り/下りに対応します。
   初期値は登録局CH15・4FSKです。
   折りたたまれている場合は右端の▼で展開します。「受信方式」コンボは折りたたみ中も表示され、他のプラグインへ切り替えられます。
   **大きなCH表示は適用済みの受信先**です。入力中は「変更は未適用」と表示し、欄からフォーカスが外れると反映します。
   以前の保存周波数は対応するCHへ自動表示し、周波数自体は変更しません。
    いずれのチャネル表にもない周波数なら「手動選局」になり、「詳細設定」タブの周波数入力を使用します。
   選局拒否時は以前の設定を維持します。方式切替時は復調器・音声・履歴をリセットします。
4. ユーザコード設定は4FSK音声のフィルタ（0～511）。**0は全UCの音声**です。制御フレームは全UCを表示します。
5. スピーカー・音量・UCは、それぞれの設定欄からフォーカスが外れると反映します。
   音声出力をONにすると、4FSK通常通信のAMBE+2音声をドングルで復号します。
   標準秘話通信は現在鍵・プリセットを優先して自動探索します。適用できる鍵がない間は消音します。
   条件を満たしたコードを発見すると、現在鍵へ自動設定・保存し、その鍵で解除した音声をドングルで復号します。
6. PSKでRICHのS=0なら、受信したUCで自動的にPN9を解除します。S=1なら、把握している
   **PSK任意コード**（0～511）を指定してください。**空欄は未設定、0は有効なコード**です。
   未設定時は、未解除TCHを保持し、解除後TCHは出しません。4FSKの秘話鍵とは別設定です。
7. 「受信」タブはCH、設定UC、受信UC、秘話・音声状態をトランシーバー風の表示で確認できます。
   RX表示はフレーム同期中に点灯し、校正された受信強度計や送信機能を示すものではありません。
   周波数、正常フレーム数、同期品質、周波数ずれ、製造者番号は「診断」にまとめています。
   「TCH」タブは「受信履歴」の選択フレームを16進表示し、選択・Ctrl+Cでコピーできます。
   最新行の選択中は最新に追従します。保存ファイルは自動作成しません。
8. 画面上部の「IQ保存（直前20秒）」または「IQ録音」タブから過去のIQを保存できます。
   復号済みの4FSK音声を保存する場合はSRdeck本体の録音機能を使用してください。

### ThumbDV / DVstick 30 を使う

Windows のデバイスマネージャーでドングルの COM 番号を確認し、「受信設定」タブの「AMBE接続先」に
`COM6` のように入力し、別の欄へフォーカスを移します。通常は 460800 baud を選び、古い ThumbDV で必要な場合は
230400 baud に変更します。ドングルは指定したCOMポートで接続し、自動検出はしません。
接続できると、受信画面の音声状態に「DVStick・音声待ち」と表示します。
音声の出力中は「DVStick音声出力」と表示します。
ポート未設定や接続・通信の失敗時は音声を出さず、受信状態の表示を続けます。
接続・通信の失敗理由は音声状態に表示します。再接続はポート設定の変更、
またはプラグインの再有効化で試みます。ほかのアプリと同じ COM ポートを同時には使えません。

AMBEserver互換サーバーを使う場合は、「AMBE接続先」に `udp://192.168.1.10:2460` を入力します。ホスト名も使え、ポート省略時は2460です。通信速度はCOM接続時のみ使用します。同じサーバーは複数の音声プラグインで同時利用できません。[共通AMBE接続の説明](../shared/Ambe/README.md)も参照してください。

`mbe-neo.dll` による音声合成とソフトウェア復号への切り替えは廃止しました。
ドングル未接続・通信失敗時は、秘話鍵が判明していても音声を出力しません。

ドングルには、プラグイン側で誤り訂正と標準秘話解除を終えた 49 ビットを
AMBE-3000 の 2450 bps / FEC なしのレート 34 で渡します。対象は 4FSK 音声のみで、
PSK の未定義な音声形式には適用しません。パケット形式・レートは
[DVSI の AMBE-3000R マニュアル](https://www.dvsinc.com/manuals/AMBE-3000R_manual.pdf) に基づきます。
2026-10-25にCOM5・460800 bpsのDVStick実機で、既知フレームの1,031 Hz音声、
秘話処理、音声抑止、ホストへの音声出力を回帰試験で確認しました。実際の無線受信音の聴取は未確認です。

## 免許局のチャネル

チャネル表は[STD-T98 2.0-E5 第3編・表3-4/3-5](https://www.arib.or.jp/english/html/overview/doc/5-STD-T98v2_0-E5.pdf#page=177)に基づきます。

| 種別 | チャネル | 周波数（MHz） |
| --- | --- | --- |
| 免許局UHF | CH1～65 | 467.000000～467.400000、6.25 kHz間隔 |
| 免許局UHF・増波 | CH66～75 | 465.096875～465.153125、6.25 kHz間隔 |
| 免許局VHF | CH1～19 | 154.443750～154.556250、6.25 kHz間隔 |
| 免許局VHF・データ用 | CH20～28 | 154.562500～154.612500、6.25 kHz間隔 |
| 中継上り（端末→中継局） | D1～D10 | 465.034375～465.090625、6.25 kHz間隔 |
| 中継下り（中継局→端末） | D1～D10 | 468.796875～468.853125、6.25 kHz間隔 |

UHFは**CH65→66で周波数が下がります**。VHFのCH20～28は音声を含まない割当として「データ用」と表示します。
中継は上り/下りのどちらか1波を選局します。同時受信や中継機能を提供するものではなく、実機の中継通話は未検証です。
RICHの予約値やメーカー独自形式を、周波数だけを理由に受け入れることはしません。

## IQの過去録音

受信中は、**選局済み48 kHz IQの直前20秒**をメモリに保持します（最大約3.84 MB）。
音声復号前のデータなので、秘話鍵が不明でも、PSKでも、同期を検出できない信号でも保存できます。
20秒に満たない場合は取得済みの長さで保存し、無音データで埋めません。

「IQ保存（直前20秒）」または「IQ録音」タブの保存ボタンを押すと、その時点のIQを切り出して背景で書き出します。
保存中に選局しても、書き出し中のIQと周波数情報は同じ時点のものを維持します。
**停止後も保存可能**です。受信の再開始、選局・設定適用、入力欠落やストリーム切り替え、プラグイン切り替えで履歴を消去します。

保存先はホストが指定するプラグインデータディレクトリ内の `captures` です。「IQ録音」の保存先欄からパスをコピーできます。

- `.wav`: PCM16 little-endian、48 kHz、2チャンネル。**左=I、右=Q**。20秒で約3.84 MB。
- `.json`: 選局周波数、CH、方式、実際の長さ、受信時刻、チャネル化の設定。秘話コードやPSK任意コードは含めません。
- `.gain`: SRdeck再生用の中心周波数。WAVと同じ場所に置くと、再生時に周波数を復元します。

IQはホストで帯域制限済みです。SDRの全帯域生IQや復号後の音声ではありません。
振幅は未校正で、`.gain` の利得0は周波数の引き継ぎ用の仮値です。受信強度の絶対測定には使用できません。
手動選局で周波数が32ビット符号付き整数の範囲を超える場合は `.gain` を作成せず、JSONの周波数を使用します。
同じCH・方式でWAVを再生すると再解析できます。実機IQの調査時にはWAV・JSON・.gainを一緒に扱ってください。

## 標準秘話の設定

ご自身の通信、または受信の許可を得た通信に使用してください。対象は**4FSKの標準PN(15,14)秘話**です。
把握している秘話コード（1～32767）を「受信設定」の現在鍵に入力し、別の欄へフォーカスを移します。
プラグインで誤り訂正・秘話解析・秘話解除を行い、AMBEドングルで音声を復号します。

現在鍵の直下には、標準秘話コードを5件まで保存できます。0は未設定です。
現在鍵が未設定で有効なプリセットが1件だけの場合は、その鍵を使います。
通常音声を受信すると、現在鍵・プリセットを優先して比較し、十分な根拠が得られなければ全32767コードを探索します。
明瞭な通常音声では最短12フレーム（約0.96秒）から判定し、不足する場合は追加音声を待ちます。
解析の計算時間もかかります。前半・後半の両方で同じ候補を十分に支持した場合だけ、現在鍵へ自動設定・保存します。
適用できる鍵がない間は消音します。プリセット一覧は書き換えません。
現在鍵は次の通話でも直ちに使用し、再確認・総当たり解析中も保持します。
音声の根拠が不足しているだけでは消音せず、別のコードが十分な根拠で確定した場合に更新します。

探索の進行状況は「受信」タブで確認できます。
秘話解析では音声を生成しないため、ドングルによる音声復号と独立して実行できます。
音声を再生できない構成でも、解析と受信状態の表示は継続します。
**解析は統計判定です。受信時間・受信誤り・音声内容によっては候補を絞れず、鍵の正しさを保証しません。**
強化秘話、PSK任意コード、メーカー独自の音声形式はこの設定の対象外です。

鍵の正否を認証する仕組みはないため、誤った鍵では正常な音声になりません。
鍵とPSK任意コードはホストの設定ファイルに保存され、機密項目として分類されますが、暗号化保存ではありません。

## 第3編 4FSK

- ホストで選局・帯域制限した48 kHz複素IQを受信。2400 symbol/s、4800 bit/s、80 msフレーム。
- ±315/±945 Hzの4FSK、α=0.2の受信H(f)/sinc(fT)フィルタ。連続履歴とCPU SIMDでFIRを処理。
- 同期ワードCDF59、周波数ずれ推定、IQ反転、フレームごとのタイミング再捕捉。
  4FSKは5サンプル間隔の位相弁別で、低振幅区間の急な位相変化の影響を抑えます。
  最良の同期候補が失敗した場合は最大2つの近傍候補を再試行します。追加候補は直前の正常フレームと時刻・制御情報が整合する場合だけ採用します。
- PN(9,5)ホワイトニング解除、RICH偶数パリティ検査。
- SACCHのデインタリーブ、パンクチャ解除、軟判定K=5ビタビ復号、CRC-6。
- UC・通話識別・製造者番号・メッセージ種別の解析。
- PICHおよびFECありTCHのCRC-12復号。PICHの9桁BCD呼出名称表示。
- AMBEチャネルの誤り訂正と、AMBE-3000ドングルによる8 kHz/16 bit/mono PCM合成。
- 通常音声、音声とデータの混在、現在鍵・プリセット・全コード探索によるPN(15,14)秘話解除。
  混在フレームではデータ区間を消音し、80 msの時間位置を維持します。
- CRC不正・UC不一致・秘話鍵未設定・終話・入力欠落・再選局で音声状態をリセット。
- 音声パラメータの連続性による標準秘話コードの自動探索。音声復号から独立して処理します。
- 直前20秒の選局済みIQをWAV・JSON・.gainとして保存。
- 概要・通話単位の最新100件の受信履歴・診断表示。選択した通話の最新データフレームをTCHタブに表示します。

## 第1編 π/4シフトQPSK

- 同じ6.25 kHzチャネル・48 kHz IQを使用。4800 symbol/s、9600 bit/s、40 msフレーム。
- α=0.2 RRC整合フィルタ（CPU SIMD）、差動位相復調。00→+π/4、01→+3π/4、10→−π/4、11→−3π/4。
- SC同期語1E56F・SB0同期語2F94D06Bの検出、IQ反転・周波数ずれ推定、毎フレームのタイミング再捕捉。
- 分割RICH（56+14 bit）を結合し、10×7デインタリーブ、K=6・R=1/2ビタビ復号、CRC-6を検証。
- F・M・S・9 bit UCを解析し、音声・非音声1/2・混在・終話を識別。
- SB0のPICHは15×8デインタリーブ、同じ畳込み復号、NULL=0とCRCを検証。9桁BCD呼出名称を表示。
- SCのTCH1=96 bitとTCH2=160 bitを抽出。PN(9,5)は毎フレーム初期化し、
  TCH1の96 bitの後、未定義領域の6 bit分も進めてからTCH2を解除。
- 任意コード不明時は受信TCHのみ。コード探索・推定は行いません。
- PSK受信ではAMBEドングルによる音声復号を行いません。

PSKの正常フレーム数は**RICH CRC通過数**です。TCHの誤り訂正・CRC・CODECは規格にないため
実装せず、TCHは未検証のビット列として扱います。PICH CRC不正なら呼出名称を表示しません。
CRCは図4-6の多項式1+X+X⁶について、初期値0・S5先頭・最終反転なしで実装しています。
第1編にはCRC初期値・読出順の明記や相互接続試験ベクトルが見当たらないため、
この規約は実機IQでの確認が必要です。復調器は周波数ずれ±900 Hz以内を探索しますが、
合成IQで確認した範囲は−350～+300 Hzです。ホストの帯域制限で欠落した信号成分は復元できません。

## 制限

第2編のRZ SSB、PSK音声、AMBE+2以外の4FSK音声方式、
製造者独自のデータ/音声形式、複数ユニットの製造者メッセージ組立、チャンネルスキャンも未対応です。
FECなしTCHは生ビット、FECありTCHはCRC検証後の情報ビットとしてモデルに保持し、
製造者固有の意味解釈は行いません。同期バーストなしの途中受信に対応しますが、
その場合は呼出名称を取得できません。

4FSKは規格掲載の試験ビット列と合成IQ、PSKは独立に符号化した合成ビット列と合成IQで検証しています。
VXD450Uでは既存の通常会話解析を確認済みです。4FSKの位相弁別改善は弱い実機IQ 1件で比較済みですが、
音声の正解ビット・聴取品質は未検証です。DJ-DPS72W・PSK、および秘話推定改善は実機IQで未検証です。
表示する同期品質は同期パターンへの適合度であり、BERや規格適合認証を示す数値ではありません。

- MSVC x64/x86 ツール（VS 2022: v143、VS 2026: v145）と CMake（VS 2022: 3.21以上、VS 2026: 4.2以上）。
- CMakeはPATH上、またはvswhereで見つかったVisual Studio同梱版を使用します。
- 自動ビルドは `-A x64` を使用するため、Visual Studio ジェネレーターが必要です。
  インストール・確認とエラー別の対処は [開発環境](https://github.com/sake846/SRdeck/wiki/Development-Environment) を参照してください。
- NuGet依存関係の初回復元にはネットワーク接続が必要です。
- 誤り訂正と秘話解析のソースは固定コミットを同梱し、ビルド中にGitHubから取得しません。
- ネイティブの誤り訂正・秘話解析は、対応ツールチェーンのReleaseビルドでLTOを使用します。

単独ビルドは `dotnet build SRdeckPlugin.AribT98/SRdeckPlugin.AribT98.csproj -c Release`。
生成される `SRdeckPlugin.AribT98.dll`、`arib_t98_fec_native.dll`、`arib_t98_analysis_native.dll`、
`SRdeckPlugin.AribT98.THIRD-PARTY-NOTICES.md` は、通常のSRdeckビルドでホスト出力先へコピーされます。
既存のSRdeckへ手動配置する場合は、この4ファイルに加えて、出力先の`System.IO.Ports.dll`と
`AMBE.THIRD-PARTY-NOTICES.md`と`licenses`フォルダーも実行ファイルと同じフォルダーへコピーしてください。
公開ソースではルートの`build.bat`を使用し、SDK・Contracts・Wpf・SignalProcessingの4パッケージを
動作確認に使うSRdeckホストと同じバージョンに揃えてください。

## 検証

以下は開発用リポジトリの回帰試験です。`SRdeck.Tests`は公開ソーススナップショットには含まれません。

```powershell
dotnet build SRdeck.Tests/SRdeck.Tests.csproj -c Release
dotnet test SRdeck.Tests/SRdeck.Tests.csproj -c Release --no-build --filter "DisplayName~ARIB STD-T98"
```

`RegressionTests.AribT98.cs` に、仕様書第3編7.5.2の独立した送信ベクトルを収録しています。
通常音声・無音・UC 1/511・呼出名称・終話・鍵129、AMBEの49ビット全一致、
誤り訂正とCRC拒否、IQ反転/周波数ずれ/クロック偏差/分割入力、雑音、音声抑止、
プラグインライフサイクル、WPF画面を検証します。
実機の音声抑止・1,031 Hz波形の試験は、`SRDECK_TEST_AMBE_PORT=COM6` のように接続先を明示した場合に実行します。
未指定の場合は実機試験をSkippedとして報告します。ソフトウェア音声合成は行いません。
画面テストはホストを模したWindow内で実行し、受信方式コンボの表示・双方向選択と、設定の折りたたみ中も切替可能なことを確認します。
CHコンボからの選択・適用済み表示・手動入力、詳細設定タブへの切替、幅540/700の描画も確認します。
`RegressionTests.AribT98Channels.cs` ではCH70→71とS05→06の周波数の飛び、呼出CH15、
旧設定の復元、設定保存、選局拒否時の表示維持、チャネル外の手動選局を検証します。
`RegressionTests.AribT98Privacy.cs` は通常音声を模した全32767コードのAMBE連続性解析、
雑音、短時間入力、キャンセル、UCフィルタ、候補の設定・保存、
設定変更・入力途切れ・受信リセット時の解析データ破棄を検証します。
`RegressionTests.AribT98Capture.cs` は20秒の保持上限、I/Qの順序、書き出し失敗後の再試行、
保存中の選局、停止後の保存、ストリーム境界、PSK、受信時刻と周波数、SRdeckでのWAV再生を検証します。

`RegressionTests.AribT98Psk.cs` は第1編の合成SC/SB0、分割RICH/PICH、CRC不正、誤り訂正、
PICHのNULL、UC/任意PN9と未定義6 bitの消費、音声抑止、RRC整形したIQの周波数ずれ・
IQ反転・±120 ppmクロック偏差・317サンプル分割入力、40 msの重複防止、途中受信、
雑音・非有限入力・リセット、PSK→4FSK→PSK切替と設定保存を検証します。
`RegressionTests.AribT98.Performance.cs` は4FSK/PSKの実時間倍率、受信時割り当て量、
無信号定常処理のゼロ割り当て、高速位相弁別の最大誤差をRelease構成で計測します。
FIRの高速化、変更前後の計測値、SIMD非対応時を含む検証は[軽量化の記録](PERFORMANCE.ja.md)を参照してください。
`RegressionTests.AribT98.ReceptionImprovements.cs` は有効無音・無効トーンの分類、連続性不足・繰り返し・途中の鍵変更、
軟判定FEC・未保護ビットの信頼度、同期再試行と誤受理抑止、IQ評価用WAVの読出しを検証します。
条件別の受信比較、秘話推定の保留率、既知鍵の実機IQ評価の実行手順と測定例は
[受信・秘話解析の改善と評価](RECEPTION-IMPROVEMENTS.ja.md)を参照してください。
PSKの合成ベクトルは実機の相互接続性を証明するものではありません。

## 配布・ライセンス

公開ソースと`with-plugins`実行パッケージの対象に含まれます。音声合成は外部のAMBEドングルで行います。
同梱するネイティブDLLは誤り訂正と秘話解析用です。`mbe-neo.dll`などのソフトウェア音声合成DLLは同梱しません。
対応するネイティブソースとビルド定義は`Native`以下に、ライセンス文書は配布物の`licenses`以下に含めます。
プラグイン単独のNuGetパッケージは作成しません。

内部処理の一部には [mbelib-neo](https://github.com/arancormonk/mbelib-neo) の
コミット `eb992d35b4b09959ff16990adf9b160e3a720ba9` を使用しています。

ARIB仕様書そのものは同梱・再配布しません。

AMBEドングルを使う構成でも、公開前には第三者ライセンスと利用条件を確認してください。
