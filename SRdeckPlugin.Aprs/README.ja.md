# APRS受信プラグイン

`aprs` はNFM上のBell 202 AFSK 1200 bit/sを受信するプラグインです。
標準チャネルサービスから48 kS/sのIQを受け取り、FM検波、1200/2200 Hz相関、
クロック回復、NRZI復号、HDLCフラグ検出・ビット詰め解除、CRC-16/X-25検証を行います。
CRC正常かつAX.25 UI / PID 0xF0のフレームだけを公開します。

## 操作

1. MODEで「アマチュア無線（APRS）」を選びます。
2. 設定で地域のプリセット、または整数Hzの受信周波数を指定します。
3. Startを押し、概要・一覧・時系列・数値グラフ・地図・診断を確認します。

既定は日本の144.660 MHz / AFSK 1200です。欧州144.800 MHz、北米144.390 MHz、
ISS 145.825 MHzのプリセットもあります。プリセットはその地域・衛星での送信や
常時運用を保証するものではありません。受信専用で、送信・digipeater・IGate・APRS-IS接続は行いません。
144.640 MHz等の9600 baud G3RUH方式には対応しません。

## 解析範囲

- AX.25の送信元・宛先SSID、最大8中継アドレス、Hビット、TNC2文字列。
- 非圧縮・base91圧縮の位置、時刻付き位置、位置曖昧度（セル中央）。
- メッセージ宛先、本文、メッセージID。ack/rejは本文として保持。
- オブジェクト／アイテムの所有者別管理、削除通知による地図マーカー除去。
- Mic-Eの位置（南北・東西、経度オフセット、位置曖昧度のセル中央）、シンボル、速度（kn）、進行方向。
- 位置付き／位置なし／圧縮位置／オブジェクトの標準気象データ。気温（°C）、風向（°）、
  風速・最大瞬間風速（m/s）、1時間・24時間・午前0時以降の雨量（mm）、湿度（%）、気圧（hPa）、日射量（W/m²）。
  位置なし気象は8桁のMDHM時刻を含む形式です。不明値のドット・空白は欠測として扱います。
- `T#`テレメトリの連番、アナログ5ch（0～255の送信値）、デジタル8bit。
  `T#MIC`の連番なし形式、Mic-E付加テレメトリ（16進数の5chまたは1・3ch）にも対応。
- ステータスの種別判定と生情報保存。
- 第三者パケット、NMEA、ベンダー固有の生気象形式、ストーム形式、base91コメントテレメトリ、
  Mic-Eの高度・ステータステキストは未解析。`PARM.`／`UNIT.`／`EQNS.`／`BITS.`定義はメッセージとして保存し、
  数値への校正は行いません。アナログ値は`raw`、デジタル値は受信ビットの0／1として表示します。
  未対応内容もCRC正常のパケットとして生本文を時系列とエクスポートに保持します。

地図は受信報告の最新位置です。受信機や中継局の位置ではありません。
非位置パケットでも直前の位置は保持します。曖昧位置のマーカーは精密測位ではありません。
一覧はセッション内で観測した局・対象別、時系列は1受信1行です。
局・対象数、画面履歴、保存履歴には上限があります（既定2,000件、設定JSON上100～10,000件）。
保存先は `%LOCALAPPDATA%\SRdeck\plugins\aprs\aprs-history.jsonl`。
保存はSDKの有界キュー経由で非同期に行い、停止時にフラッシュします。
時系列の「履歴を保存」からJSON／CSV／TNC2に出力できます。地図は共通WebView2と地図設定を使います。
JSONには解析済みの気象・テレメトリ構造を含め、CSVには単位付き列名で数値を追加します。TNC2は生本文です。
旧バージョンの保存履歴も起動時に生本文を再解析するため、保持範囲内の値をグラフに表示できます。

「数値グラフ」で局・対象と項目を選びます。横軸は受信時刻（端末の現地時刻）、縦軸は選択項目の単位です。
送信側の時刻やテレメトリ連番では並べません。局・対象ごとに分離し、保持中の履歴を時刻順に描きます。
欠測値は0に置換せず除外します。アナログ値は点を線で結び、デジタル値は階段状に表示します。
グラフ上のポインター、または左右／Home／Endキーで受信値を確認できます。下の表からも時刻と値を読めます。
新しい局を受信しても選択は保持し、選択局の履歴が保持上限から消えた場合は残っている局へ切り替えます。

## ビルド・検証

```powershell
dotnet build SRdeckPlugin.Aprs/SRdeckPlugin.Aprs.csproj -c Release
dotnet run --project tests/Aprs/Aprs.Tests.csproj -c Release -p:RuntimeIdentifier=win-x64
dotnet test SRdeck.Tests/SRdeck.Tests.csproj -c Release --filter "DisplayName~APRS"
```

Linuxでは2番目のRIDを`linux-x64`にします。移植可能な試験は本番DSP・解析ソースをリンクし、
独立CRC実装、CRC既知値`123456789 → 0x906e`、APRS101圧縮位置の例、
合成FM IQの54条件（CFO ±1 kHz／0、±150 ppm／0、IQ反転、1／731／4096サンプル境界）、
ビット詰め、破損・切断、不連続リセット、ノイズ、上限と定常割り当てを検証します。
Windowsの共通回帰カタログにも同じ試験とホスト・ビュー・履歴試験を登録します。
数値解析・グラフの入力、期待値、実行結果は[検証記録](VALIDATION.ja.md)を参照してください。
合成IQの試験は実波での感度・復号率を保証しません。実波・Windows GUIの実機動作は別途検証が必要です。

### 回帰試験レビュー

- 正常系: UI/PID、位置・メッセージ・所有者別対象、地図、履歴と3形式の出力。
- 拡張: APRS101のMic-E例、経度オフセット境界、曖昧度4段階、気象の単位・0・負温度・欠測、
  テレメトリのチャンネル順と不正値、JSON往復、旧履歴の再解析、CSV数値列、グラフの選択・時刻順・保持上限・WPF描画。
- 異常系: CRC破損、アドレス不正、フレーム上限、切断、ノイズ、未対応形式、設定不正。
- 状態: ウォームアップ非公開、停止後非公開、ドロップ時リセット、再開、同調拒否／保留、再起動復元。
- 資源: 固定DSPバッファ、入力リース非保持、有界履歴・局数・保存キュー、停止フラッシュ。
- 共通境界: Contracts/SDK/WPFだけを参照し、ホストの方式固有分岐は追加しません。
