# 周波数ごとの活動ヒートマップ

プラグインID: `activity-heatmap`。スペクトラム画面の表示範囲、または受信帯域全体を256セルに分け、周波数別の活動率を長時間監視します。別の受信プラグインと同時に有効化でき、同調やサンプルレートの変更は要求しません。

プラグイン一覧で「周波数ごとの活動ヒートマップ」を選択して受信を開始します。横軸は周波数、縦軸は時刻で、ウォーターフォールと同じく最新が上、過去が下です。色は各セル内のFFTビンの最大電力がしきい値以上だった観測の割合（0〜100%）です。灰色は未観測で、無信号の0%と区別します。最新の行は集計途中です。マウスまたは矢印キーで周波数範囲・時刻・活動率・観測回数・判定しきい値を確認できます。

「活動判定のしきい値」は既定 −100 dBm（FFTビン単位）、−140〜−20 dBmを10 dB刻みで変更できます。スペクトラムとウォーターフォールが使うFFT結果へ同じ受信機校正を適用した値で判定します。共有スペクトラムがない場合は「スペクトラム待ち / 未観測」と表示し、値を仮定した集計はしません。

表示期間は1時間・6時間・24時間から選べます。既定は6時間です。1時間・6時間表示では1行1分、24時間表示では1行4分にまとめます。元の1分集計を最大24時間保持するため、期間を切り替えても履歴は失われません。集約時は各区間の観測回数で重み付けし、欠落区間を無信号として数えません。通常のサンプル欠落でも蓄積済み履歴を保ちます。可視化の更新は約1回/秒です。

「範囲」の既定は「スペクトラムに追従」です。画面のズーム・パン後の周波数範囲に横軸を合わせます。
「受信帯域全体」へ切り替えると、画面の操作から独立して入力帯域を監視します。入力帯域外まで表示した場合は、
取得できない部分だけが灰色の未観測になります。範囲の切り替え、追従中のズーム・パンでは列の周波数が変わるため履歴をリセットします。

独自FFTは実行せず、汎用の `IPluginSpectrumService` からホストと同じ周波数分解能・窓・正規化・ゲイン補正のデータを取得します。各表示セルは対応周波数範囲の最大値で判定し、同じ範囲の同じFFTフレームを重複計上しません。表示セル幅は選択中の周波数範囲÷256です。FFTの更新間隔より短い信号を見逃す場合があり、連続時間の厳密な占有率ではありません。dBm値の精度はホスト側の受信機校正に依存します。

履歴クリア、しきい値変更、受信再開、ストリーム・世代・同調・入力レート変更やサンプル位置の巻き戻りで履歴をリセットし、異なる条件を混ぜません。停止中は最後の履歴を保持し、表示期間を変更できます。履歴はメモリ内だけに保持し、保存やエクスポートは行いません。しきい値と表示期間はアプリ起動ごとに既定値へ戻ります。

追加のネイティブDLLは不要です。Windows x64 / .NET 10 WPF。ライセンス: GPL-3.0-only。
