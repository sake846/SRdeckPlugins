# FT8プラグイン改善提案

## 目的

この文書は、現在の実装を否定する不具合一覧ではなく、次の開発サイクルで検討する改善候補を、効果、実装順、検証可能な完了条件とともに整理したものです。FT8だけでなく、同じ受信経路を使うFT4とJT65Aも対象に含めます。

## 現状の強み

- FT8、FT4、JT65AをUTCスロットに合わせて復号し、候補探索、誤り訂正、CRC確認までプラグイン内で完結しています。
- 複数信号の復号、強信号除去後の再探索、近接バンドの同時受信に対応しています。
- 受信履歴、局一覧、Maidenheadロケータによる地図表示、ウォーターフォール注釈、CSV/JSON出力、直前20秒のIQ保存がそろっています。
- 候補数、同期スコア、誤り訂正の反復回数、復号時間などの診断値をすでに取得しており、改善効果を測定する土台があります。

## 推奨ロードマップ

### 優先順位の判断基準

| 優先度 | 判断基準 | 着手判断 |
|---|---|---|
| P0 | 後続の改善を正しく評価するための前提、または受信結果の意味を左右する互換性 | 次の開発サイクルで着手する |
| P1 | 感度、リアルタイム性、問題切り分けを直接改善する | P0の基準値を取得してから着手する |
| P2 | 運用上の利便性や外部活用を広げる | コア復号の品質を維持できる状態で個別に判断する |

工数は実装前の相対見積もりです。`S`は局所的な変更、`M`は複数コンポーネントにまたがる変更、`L`はデータ形式または外部仕様の調査を伴う変更を表します。

| 項目 | 効果 | 工数 | 主な依存関係 |
|---|---:|---:|---|
| 実録コーパスとベンチマーク | 高 | M | なし |
| メッセージ種別の構造化復号 | 高 | L | 仕様ベクトル、往復テスト |
| 時刻・周波数ずれへの耐性 | 高 | L | コーパス、性能予算 |
| 適応的な負荷制御 | 高 | M | 復号時間ベンチマーク |
| 診断UI | 中 | M | 診断値の追加 |
| 局・履歴ワークフロー | 中 | M | UI性能測定 |
| オプトインのスポット連携 | 中 | L | データモデル、同意設計 |

### P0: 実録コーパスと再現可能な復号ベンチマーク

**狙い:** アルゴリズム変更を「復号件数が増えた」だけで評価せず、取りこぼし、誤復号、処理時間を同じ入力で比較できるようにします。

**提案:** ノイズのみ、単一信号、周波数重複、時刻ずれ、周波数ドリフト、過大入力、スロット境界の欠落を含む、権利関係を明示した小さなIQコーパスを用意します。モード、期待メッセージ、許容周波数・時刻誤差を機械可読なマニフェストに記録し、CIでは短い代表セット、手動ベンチマークでは全セットを実行します。

**完了条件:**

- 同一入力に対して、再現率、誤検出数、重複数、スロット当たりの処理時間、最大割り当て量をレポートできる。
- FT8、FT4、JT65Aについて、最低1件ずつ実録または独立生成した既知信号を継続テストする。
- 閾値を変更するPRでは、基準ブランチとの差分を添付できる。

### P0: メッセージ種別の完全な構造化復号

**狙い:** コンテストや特殊運用のメッセージをRAW表示で終わらせず、検索、局集計、外部連携に利用できる形にします。

**提案:** 現在RAW表示となるDXペディション、EU VHFコンテスト、ARRL Field Day、ARRL RTTY、WWROFコンテストの各77ビット形式を段階的に実装します。表示文字列とは別に、コールサイン、レポート、交換番号などを型付きフィールドとして保持し、未知・予約形式は従来どおり安全にRAWへフォールバックします。

**完了条件:**

- 各対応形式について、公開仕様から作成した正常系ベクトルと境界値ベクトルがある。
- 復号したペイロードを再符号化した結果が元の77ビットと一致する往復テストがある。
- 未知形式でも例外を発生させず、ペイロードを失わない。

### P1: 時刻・周波数ずれと弱信号への耐性向上

**狙い:** PC時刻の小さなずれ、発振器誤差、移動体・衛星・散乱伝搬によるドリフトがある信号の取りこぼしを減らします。

**提案:** 粗探索後の時刻・周波数推定を可視化し、必要に応じて探索範囲を段階的に広げます。線形周波数ドリフト仮説を追加する場合は、常時総当たりにせず、同期スコアが惜しい候補だけを再評価します。また、観測された時刻オフセットの中央値を「時計ずれの目安」として表示し、自動的なOS時計変更は行いません。

**実装状況:** 直前区間で復号した信号のDTについて、外れ値の影響を受けにくい符号付き中央値を概要画面に表示します。探索範囲の拡張とドリフト仮説は未実装です。

**完了条件:**

- P0コーパスに定義した時刻ずれ・周波数ずれ・ドリフト条件で、基準値以上の再現率を満たす。
- ノイズのみの入力で誤検出率が既存基準を超えない。
- 1スロットの処理が次のスロット開始までに完了し、超過時は診断画面で判別できる。

### P1: 適応的な負荷制御とメモリ再利用

**狙い:** 広帯域・複数バンド受信時にもUIと次スロットの処理を滞らせないようにします。

**提案:** 候補探索、微細同期、除去パスごとの所要時間と候補削減数を計測します。候補配列、スペクトログラム、尤度バッファにはプールまたは再利用可能な作業領域を検討します。処理時間がスロット予算に近づいた場合は、低スコア候補、追加除去パス、追加バンドの順で制限する明示的な負荷制御を導入します。

**実装状況:** 直前の復号時間をモード別スロット長に対する使用率として診断画面に表示し、100%以上では警告と負荷を下げる操作を案内します。候補の自動制限と作業領域の再利用は未実装です。

**完了条件:**

- 代表的な15秒FT8スロットについて、ウォームアップ後の割り当て量とp50/p95復号時間を自動計測できる。
- 負荷制御が働いた理由と省略候補数が診断値に現れる。
- 入力順やスレッド数にかかわらず、同じ候補の優先順位と結果を再現できる。

### P1: 受信品質を判断しやすい診断UI

**狙い:** 「復号できない」原因を、無信号、過小・過大入力、時計ずれ、候補過多、復号失敗に切り分けやすくします。

**提案:** 既存の入力レベル、候補数、LDPC/CRC棄却数、最終復号時間に、クリップ率、ノイズフロア、推定時刻ずれ、推定周波数ずれ、処理予算使用率を加えます。設定値には推奨範囲のツールチップを付け、「標準」「弱信号優先」「低負荷」のプリセットから開始して詳細設定で上書きできるようにします。

**実装状況:** 処理予算使用率、候補上限到達、IQクリップ率を個別に判定し、負荷状況に応じた確認操作を診断画面に表示します。コールサイン、メッセージ、IQデータを含まない共有用診断テキストに加え、「標準」「弱信号優先」「低負荷」の復号プリセットを提供します。手動入力値もUIに表示した範囲へ即座に正規化します。ノイズフロアと周波数ずれは未実装です。

**完了条件:**

- 無信号、クリッピング、時刻ずれ、候補上限到達、処理時間超過を個別の状態として表示できる。
- プリセットの適用後も個々の詳細値を確認でき、設定の正規化範囲とUI表示が一致する。
- 診断情報を個人情報やIQデータを含めずにテキストとしてコピーできる。

### P2: 局・履歴ワークフローの強化

**狙い:** 長時間受信後に、重要な局や伝搬傾向を素早く見つけられるようにします。

**提案:** バンド、モード、メッセージ種別、SNR範囲、ロケータ有無、時刻範囲による複合フィルタと列ソートを追加します。同一局について初回・最終受信、最良SNR、受信バンド数を集計し、保存済みJSONLからの再構築も同じ規則にします。UTCとローカル時刻の表示切替も用意します。

**完了条件:**

- 1万件の履歴でフィルタ操作を行ってもUIスレッドを長時間占有しない。
- 画面上のフィルタ条件をCSV/JSONエクスポートにも選択的に適用できる。
- 夏時間を含む日時について、保存値はUTCのまま、表示だけを安全に切り替えられる。

### P2: オプトインのスポット連携

**狙い:** 復号結果を既存のアマチュア無線エコシステムで活用できるようにします。

**提案:** ADIF出力を先に実装し、その後PSK Reporterなどへの送信を独立機能として検討します。ネットワーク送信は既定で無効にし、送信先、送信項目、自局コールサイン・ロケータ、再送・レート制限、保存期間を画面に明示します。

**完了条件:**

- ネットワーク連携は明示的な同意なしには一切送信しない。
- オフライン、タイムアウト、送信先エラーが復号処理を妨げない。
- 重複スポットを抑止し、キュー上限と破棄件数を診断できる。

## 実装順の考え方

まずP0で評価尺度とプロトコル互換性を固めます。その後、同じベンチマークを使ってP1の感度・性能改善を進めると、性能向上と誤検出のトレードオフを説明できます。P2は利用価値が高い一方、履歴の意味やプライバシー境界に影響するため、データモデルと同意画面を先に設計します。

## 最初の実装単位

最初のPRは機能追加を混ぜず、P0のベンチマーク基盤に限定します。

1. `testdata/ft8/`に、ノイズ、単一FT8信号、重複する2信号の最小3ケースとマニフェストを追加する。
2. `SRdeck.Tests`から同じ受信経路へ入力し、期待ペイロード、周波数、時刻、重複数を検証する。
3. Release構成で復号時間と割り当て量を測る任意実行のベンチマーク入口を追加する。
4. CI用の正否テストと、環境差の影響を受ける性能レポートを分離する。

この単位の完了後に基準値を記録し、構造化復号と同期耐性のどちらを先に実装するかを、コーパス上の失敗件数から決定します。これにより、未計測の最適化や一度に広範囲を変更することを避けます。

## 現行実装との対応

| 観点 | 現行の主な実装箇所 | 改善時に確認すること |
|---|---|---|
| スロット処理と診断値 | `Dsp/Ft8Receiver.cs` | モード別スロット境界、処理時間、連続性 |
| FT8候補探索・微細同期・除去 | `Dsp/Ft8Decoder*.cs` | 再現率、重複、誤検出、処理予算 |
| FT4/JT65A復号 | `Dsp/Ft4Decoder.cs`, `Dsp/Jt65Decoder.cs` | FT8向け変更による回帰がないこと |
| 77ビットメッセージ | `Protocols/Ft8Codec.cs` | 未知形式のRAW保持、既知形式の往復 |
| 設定の範囲 | `Ft8Settings.cs` | UI表示、永続化、正規化結果の一致 |
| 履歴・局・地図 | `ViewModels/Ft8ViewModel.cs` | 大量履歴時の応答性とUTC保持 |
| 既存回帰テスト | `SRdeck.Tests/RegressionTests.Ft8.cs` | 新しい実録ケースと既存合成ケースの併用 |

## 対象外

- この文書だけを根拠に、送信機能や自動交信機能は追加しません。本プラグインの現在の責務は受信・復号です。
- 復号率向上のためにCRCを省略したり、未検証の結果を通常の受信結果として公開したりしません。
- 診断目的であっても、ユーザーの明示的な操作なしにIQ録音や局情報を外部送信しません。
